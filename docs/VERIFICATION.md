# Локальная проверка миграции на Go

Проверка выполнена 20 октября 2026 года. По согласованию с владельцем объём проверки ограничен локальным окружением. Реальные SMS, вход Kaspi, создание платежей, возвраты и доставка Telegram на настоящие учётные записи не выполнялись.

## Источники сравнения

- `175577e` — исходная Node-версия до добавления сервисной авторизации.
- `d554ab2` — последняя Node-версия перед переносом на Go.
- Сопоставлены все исходные маршруты auth, invoice, QR, history, refund, session, формирование подписей и статусы фонового polling. Контракты платёжных запросов зафиксированы в `internal/app/compatibility_test.go` со ссылкой на исходный коммит.
- SQLite и завершённая история удалены по отдельному требованию владельца. Сессия Kaspi управляется сервером; интеграции используют сервисные Bearer-ключи. Панель использует пароль и cookie.

## Воспроизведение

```text
go test ./cmd/... ./internal/...
go vet ./cmd/... ./internal/...
cd web
pnpm build
```

Для ручного прогона браузера есть изолированный fixture, который не читает `.env` и настоящее состояние, не обращается в Kaspi и Telegram. В PowerShell из корня проекта:

```powershell
$env:KASPI_BROWSER_SMOKE='1'
go test ./internal/app -run '^TestBrowserSmokeServer$' -count=1 -timeout=20m -v
```

Откройте `http://127.0.0.1:38473`. Тестовый пользователь: `smoke-owner`, тестовый пароль: `smoke-test-only-password-2026`. Эти значения предназначены только для локального fixture. Все его платёжные запросы направляются на локальный mock. После проверки остановите процесс и удалите переменную `KASPI_BROWSER_SMOKE` из текущего окружения.

Успешные локальные проверки подтверждают контракт и поведение реализации. Доступность приватного API Kaspi для конкретного аккаунта и актуальность профиля приложения требуют отдельной проверки с владельцем аккаунта.

## Сверка с предоставленной рабочей интеграцией

Дополнительно изучены платёжные участки рабочей Python-версии: `kaspi_server.py` (`_compute_token_sn_mac`, `_make_api_headers`, `api_check_client`, `api_create_invoice`, `api_history`, `api_operation_details`, `_check_details_status`, `_check_token_alive`, keepalive и выборка `v02/history/operations`) и `kaspi_bot.py` (нормализация телефона, поиск и создание счёта). Исходный проект не изменялся. Его реальные токены, данные клиентов, базы и настройки не переносились.

| Требование рабочего поведения | Доказательство в нашем сервисе |
| --- | --- |
| MAC вычисляется заново, меняется на границе 30 секунд; challenge ограничен 32 байтами | Шесть синтетических векторов вычислены отдельным вызовом чистой Python-функции; совпадают в `TestWorkingReferenceMACVectors` |
| Платёжные запросы используют сессию SMS-входа и её device/install/profile | `TestWorkingReferencePaymentRequests`: пути, методы, JSON-поля, собственные заголовки устройства и проверка ECDSA-подписи |
| Телефоны `+7`, `8`, со скобками/пробелами/дефисами | Контракт поиска и счёта, `TestFormattedSMSPhone`, валидация панели; в Kaspi уходит нормализованный номер |
| Read-only проверка подключения через remote history | Контракт `MaxResult: 1`; существующие тесты потери связи и Telegram переведены на этот endpoint |
| Выборка истории счетов и проведённых операций | Проверены `MaxResult: 600` и дневная выборка `StartDate/EndDate/PageSize/PaymentType/LastTransactionDate/StatementPeriodCode`; параметры доступны через API |
| Оплаченный счёт может исчезнуть из remote history | Статус незавершённого счёта проверяется по `v02/remote/details`, завершённые операции читаются из `v02/history/operations` |
| Сохранение незавершённого счёта при потере токена/связи | `TestPendingInvoiceResumesAfterOutageAndRestart`: 12 ошибок HTTP/JSON или кодов `-10001`/`-101001`, backoff, восстановление с диска, повторное подключение и success-вебхук для счёта старше 24 часов |
| Суммы истории в виде `1 250 ₸` | Панель разбирает форматированные суммы; в браузере проверены `2 500 ₸` в сводке и строке операции, а также поиск клиента по `+7 (700) 123-45-67` |

Отдельный SMS POS-сервис, на который ссылается рабочая Python-версия, в предоставленной директории отсутствует. Её Flask-маршруты только проксируют SMS-сессию; поэтому независимым источником для внутренних шагов SMS-входа остаётся исходная Node-реализация и её локальный end-to-end контракт. Криптографические форматы локальных файлов разных проектов не смешиваются: наш сервис самостоятельно получает и шифрует свою сессию.

Перенос биллинга, массовой рассылки, PostgreSQL, архива завершённых счетов и чужих бизнес-процессов не выполнялся. Настоящее создание/оплата счёта и SMS-вход на аккаунте владельца этой проверкой не подтверждены: используются только локальные HTTP-серверы с синтетическими данными, согласно ранее выбранному объёму проверки.

## Интервал отправки счетов

`INVOICE_SEND_INTERVAL` задаёт одну общую паузу между отправками счетов, без дополнительных пакетных пауз. В `invoice_limiter_test.go` проверены четыре одновременных запроса с двумя разными сервисными ключами, соблюдение интервала после отказа Kaspi, немедленная первая отправка, отмена ожидающего запроса и доступность поиска, истории, QR и возврата во время отправки счёта. Конфигурационные тесты проверяют значение по умолчанию `7s`, отключение через `0s`, пользовательское значение и отклонение некорректных интервалов. Полный набор Go-тестов и сборка Vue проходят.
