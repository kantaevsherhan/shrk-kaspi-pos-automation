# Локальная проверка миграции на Go

Проверка выполнена 20 октября 2026 года. По согласованию с владельцем объём проверки ограничен локальным окружением. Реальные SMS, вход Kaspi, создание платежей, возвраты и доставка Telegram на настоящие учётные записи не выполнялись.

## Источники сравнения

- `175577e` — исходная Node-версия до добавления сервисной авторизации.
- `d554ab2` — последняя Node-версия перед переносом на Go.
- Сопоставлены все исходные маршруты auth, invoice, QR, history, refund, session, формирование подписей и статусы фонового polling. Контракты платёжных запросов зафиксированы в `internal/app/compatibility_test.go` со ссылкой на исходный коммит.
- SQLite и завершённая история удалены по отдельному требованию владельца. Сессия Kaspi управляется сервером; интеграции используют сервисные Bearer-ключи. Панель использует пароль и cookie.

## Подтверждённые проверки

| Область | Проверка |
| --- | --- |
| SMS-вход | init → phone → OTP → finish → org context на локальном HTTP-сервере; передача обновлённого cookie и параметров каждого шага |
| Криптография | независимая проверка ECDSA-подписей заголовков по алгоритму Node, подпись данных входа, ECDH P-256, фиксированный TokenSnMac, шифрование и восстановление сессии |
| Платёжный API | методы, пути, JSON-поля и типы всех исходных маршрутов, числовые/строковые ID и суммы, оригинальная и преобразованная QR-ссылка |
| Ошибки | HTTP 401 upstream не считается действующей сессией; ошибочный StatusCode не считается успехом; некорректный ввод отклоняется до обращения к Kaspi |
| Совместимость | восстановлен POST `/api/auth/session`; `/health` возвращает совместимое поле `status`; ID с ведущими нулями обрабатываются как десятичные |
| Состояние | конкурентные записи платежей и сессий; восстановление после перезапуска; миграция старых JSON-файлов; отсутствие открытого Kaspi-токена в файле сессии |
| Polling | завершённые статусы, QR с временем `+0500`, истечение QR без сессии, защита от проверки платежа другой организации |
| Вебхуки | HMAC-подпись, повтор после HTTP-ошибки, сохранение доставки на диске во время HTTP-запроса, удаление после подтверждения |
| Пароль панели | первоначальная настройка, хеш вместо пароля, вход/выход, cookie, ограничение одновременных попыток, защита POST от другого origin |
| Telegram | локальный mock Bot API: потеря связи, три сетевые ошибки подряд, восстановление, отсутствие повторного сообщения после перезапуска, тестовое сообщение и отсутствие токена в ошибках |
| Интерфейс | вход и обновление страницы, поиск клиента, создание и отмена счёта, автоматический статус QR, история, подробности и возврат доступной суммы; выход сохраняется после обновления |
| Мобильный экран | меню и подробности операции на ширине 390 px; исправлен выход диалога за границы экрана |
| Запуск | production-сборка Vue, Go vet, Docker build и запуск контейнера с временными ключами; HTTP 200 на health/панели, HTTP 401 на API без ключа |

## Воспроизведение

```text
go test ./cmd/... ./internal/...
go vet ./cmd/... ./internal/...
cd web
pnpm build
```

Для ручного прогона браузера есть изолированный fixture, который не читает `.env` и настоящее состояние, не обращается в Kaspi и Telegram. В PowerShell из корня проекта:

```powershell
$env:KASPI_BROWSER_SMOKE='1'
go test ./internal/app -run '^TestBrowserSmokeServer$' -count=1 -timeout=20m -v
```

Откройте `http://127.0.0.1:38473`. Тестовый пользователь: `smoke-owner`, тестовый пароль: `smoke-test-only-password-2026`. Эти значения предназначены только для локального fixture. Все его платёжные запросы направляются на локальный mock. После проверки остановите процесс и удалите переменную `KASPI_BROWSER_SMOKE` из текущего окружения.

Успешные локальные проверки подтверждают контракт и поведение реализации. Доступность приватного API Kaspi для конкретного аккаунта и актуальность профиля приложения требуют отдельной проверки с владельцем аккаунта.
