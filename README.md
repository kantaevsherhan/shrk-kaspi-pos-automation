# Kaspi POS Automation

Автоматизация платежей для POS-систем через Kaspi Pay API. Проект предоставляет серверное приложение и веб-интерфейс для создания счетов, генерации QR-кодов, просмотра истории транзакций и оформления возвратов.

> Интеграция использует внутренние интерфейсы Kaspi Pay. Их формат и требования к версии приложения могут измениться. Операции с реальным Kaspi аккаунтом в этой разработке не проверялись.

## Сервисный режим

После SMS-входа кассира сессия Kaspi хранится на сервере в зашифрованном виде. Другие приложения обращаются к `/api/*` с `Authorization: Bearer <ключ>`; заголовки Kaspi им больше не нужны. `SERVICE_API_KEYS` задаёт несколько именованных ключей. Все ключи имеют доступ к **одному подключённому Kaspi аккаунту** и могут создавать счета, QR и возвраты.

SQLite хранит, **какой сервис** создал счёт или QR, номер получателя, сумму, комментарий и последний известный статус. История Kaspi доступна через существующие эндпоинты, но не содержит идентификатор вашего сервиса. Журнал каждого ключа виден только этому ключу: `GET /api/audit/requests?limit=50&offset=0`.

Проверка состояния без авторизации: `GET /health`.

Состояние сервиса хранится в `STATE_DIR`: идентификатор устройства, ключи, SQLite, отслеживаемые платежи и очередь вебхуков. Сохраняйте этот каталог между перезапусками.

### Webhooks

Сервер автоматически отслеживает статусы созданных QR- и invoice-платежей (polling каждые 3 сек.) и отправляет HTTP POST-уведомления на указанные URL при изменении статуса.

- 📡 **События:** `payment.success` · `payment.failed` · `payment.expired` · `payment.lost`
- ⚙️ **Настройка:** файл `STATE_DIR/webhooks.json` (см. [`webhooks.example.json`](./webhooks.example.json)); путь можно изменить через `WEBHOOKS_FILE`
- 🔐 **Подпись:** HMAC SHA-256
- 🔄 **Retry:** до 3 попыток с нарастающей задержкой

> 📖 Подробнее — в [документации API](./docs/API.md#webhooks--уведомления).

## Быстрый старт

```bash
# 1. Клонировать репозиторий
git clone https://github.com/tapter-dev/kaspi-pos-automation.git
cd kaspi-pos-automation

# 2. Установить зависимости
npm install

# 3. Создать .env по образцу .env.example
# TOKEN_SECRET_KEY — 64 hex-символа; SERVICE_API_KEYS — JSON со случайными ключами от 32 символов

# 4. (Опционально) Настроить вебхуки
cp webhooks.example.json webhooks.json
# Отредактируйте webhooks.json под свои нужды

# 5. Запустить сервер
npm start
```

В PowerShell можно получить ключи так:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Для Docker: заполните `.env`, затем `docker compose up -d --build`. Том `kaspi_data` сохраняет SQLite и идентификатор устройства. Compose публикует порт только на `127.0.0.1:3000`; для внешнего доступа используйте TLS reverse proxy.

Пример обращения из другого сервиса после SMS-входа в веб-панели:

```bash
curl -X POST http://127.0.0.1:3000/api/invoice/create \
  -H 'Authorization: Bearer YOUR_SERVICE_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"phoneNumber":"77001234567","amount":1000,"comment":"Заказ 42"}'
```

Резервируйте `STATE_DIR` вместе с `TOKEN_SECRET_KEY`. Потеря ключа шифрования делает сохранённую сессию Kaspi нечитаемой; тогда потребуется новый SMS-вход.

При первом запуске автоматически генерируются `keypair.json` и `device.json`.

| `APP_MODEL`        | Модель устройства                        | `iPhone16,2`               | Нет          |
| `APP_BRAND`        | Бренд устройства                         | `Apple`                    | Нет          |

## Демо-интерфейс (`public/`)

В папке `public/` находится встроенный веб-интерфейс (SPA), который запускается автоматически вместе с сервером и доступен по адресу `http://localhost:3000`.

**Возможности интерфейса:**

- 🔐 **Авторизация** — вход по номеру телефона кассира Kaspi Pay через 3-шаговый SMS-flow (ввод номера → OTP-код → завершение)
- 🧾 **Выставление счёта** — создание счёта по номеру телефона клиента с указанием суммы и комментария
- 📱 **QR-оплата** — генерация QR-кода для оплаты с отслеживанием статуса в реальном времени
- 📋 **История операций** — просмотр списка транзакций с детализацией
- 💰 **Продажи и возвраты** — статистика продаж и оформление возвратов

**Файлы:**

| Файл | Описание |
| --- | --- |
| `public/index.html` | HTML-разметка и стили интерфейса |
| `public/app.js` | Клиентская логика (API-вызовы, управление состоянием) |

Вход в панель начинается с Bearer-ключа, затем кассир подключает Kaspi по SMS. Ключ браузера хранится только в текущей вкладке. Панель показывает ссылку оплаты; QR-картинка создаётся через сторонний `api.qrserver.com` только после отдельного нажатия. При этом ссылка передаётся этому сервису. Для полностью локального QR используйте `QrOriginalToken` из API в своём генераторе.

## Единый QR — приём платежей от других банков

При создании QR-кода через `/api/qr/create` в ответе возвращаются два поля:

- **`QrToken`** — ссылка вида `https://pay.kaspi.kz/pay/...`, работает только в приложении Kaspi.
- **`QrOriginalToken`** — оригинальная ссылка вида `https://qr.kaspi.kz/...`, поддерживает оплату через **Единый QR** (приложения других банков).

Чтобы клиенты могли оплачивать через приложения других банков, генерируйте QR-код из значения **`QrOriginalToken`**, а не из `QrToken`.
